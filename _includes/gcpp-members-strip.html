{% comment %} Homepage member-group strip — the "spinning std::tuple" that replaced the flat logos/tuple_banner_dark.png. Params: (none). Data: every _data/members/.yml, in slug order (same order as /members/). Assets: /logos/members/.* (the group's own logo) wins; /logos/flags/.* (city or national flag) is the fallback; a group with neither renders a monospace city tile. Existence is tested against site.static_files, because GitHub Pages' Jekyll has no file-exists filter — so a missing or misnamed asset can never emit a broken . An optional `logo:` key on the member file overrides both directories. Hover: data-gcpp-tip is the tooltip text, rendered by CSS ::after. It is NOT a JS hook and must not be a `title` attribute — the link's accessible name already comes from the image alt, and a title would double-announce it. Motion: pure CSS marquee (assets/css/main.scss); no JavaScript. The track holds exactly TWO identical copies of the list so translateX(-50%) loops seamlessly; copy 2 is decorative (aria-hidden + tabindex="-1") and is display:none under prefers-reduced-motion, where the strip becomes a static wrapped grid. If the group list ever shrinks below the viewport width, go to three copies and -33.3333%. The last cell of copy 1 is tagged --tail so the static view can drop its trailing comma (the marquee needs it: it is the gap before the loop wraps). {% endcomment %} {%- assign member_logos = site.static_files | where_exp: "f", "f.path contains '/logos/members/'" -%} {%- assign member_flags = site.static_files | where_exp: "f", "f.path contains '/logos/flags/'" -%} {%- assign groups = site.data.members | sort -%}
